# How it works

## How I use it

My real system is an Excel workbook with a VBA engine and small Python import scripts, not this code. Once a month I
download the bank statement and the credit-card bill, run the import, check the totals and press the consolidate
buttons; shops the rules do not know show up in a list and I pick their category by hand, adding a rule when the shop
repeats. Every week, and again at the end of the month, I close the cash flow from that workbook. This repository
rebuilds the same monthly cycle in Python and adds one thing my workbook does not have: the AI suggestion, with how
sure it is, for the shops I used to sort by hand. Nothing runs on a schedule; I start each step.

## The steps

1. **Read the statement** and check that every balance adds up, line by line.
2. **Store it** in a small database file (`data/ledger.sqlite`, SQLite) that keeps every transaction once, so loading
   the same file twice, or two statements that overlap, adds nothing. The reports read from this file.
3. **Skip money moved between your own accounts**, investments, card bill payments and cash withdrawals: they are not
   spending.
4. **Apply the rules** in `data/rules.csv`: a word in the description gives the category (the longest match wins; a
   rule can also depend on whether money came in or went out, or on the amount).
5. **Ask Claude about the rest**: only shops it has not seen before, 20 at a time, with people's names removed. It
   answers with a category, how sure it is, and a short keyword for a future rule. The code checks the answer before
   using it.
6. **A person confirms the doubtful ones.** Sure answers (0.8 or more) are used; the others wait in a review list. A
   confirmed answer is saved as a new rule, so next month that shop costs nothing.

## What the demo does

`python demo.py` creates three made-up statements, loads them, loads the first month again (nothing is added),
confirms the AI suggestions that name a clear category (a guess of "Other" waits for a person), writes the monthly
reports to `output/`, checks the AI against the answer key (`output/eval.md`) and writes `final-report.pdf`.

The AI answers used by the demo are saved in `data/recorded/`, so the demo runs without an API key and costs nothing.
With a key, only questions that were never asked before are sent, and each one is saved. Every call is logged in
`output/logs/` with its token count and estimated cost.

Results on the made-up statements:

| | |
|---|---|
| Transactions sorted by the fixed rules | 7 in 10 |
| Shops the AI had to look at | 13 in the first month, 9 in each of the next two |
| AI answers that were right, on 31 shops whose category is already known | 30 |
| New rows when the same statement is loaded twice | 0 |
| Cost of all the AI answers saved for the demo | less than one US cent |

The one wrong answer (an online video course filed as Subscriptions instead of Education) came with confidence 0.85,
above the 0.8 limit, so it would have been used without review. The evaluation lists every case like this.

## Data

All data is synthetic, generated by `generate_data.py`: three statements with invented shops and amounts, the
starting rules, and 31 shop names whose right category is already known, used as an answer key to check the AI
(`tests/golden/labels.csv`). No real statement, balance or shop list is used.

This is a public rewrite of a tool I use every month. The original is an Excel workbook with a VBA engine (buttons to
consolidate the month, a category menu on each line, undo, a dashboard and a cash-flow sheet), fed by Python scripts
that also read the credit-card bill from PDF. None of that is included here, and the original has no AI step.

## Statement format

A CSV file (a table saved as plain text) as exported by many Brazilian banks: columns separated by `;`, numbers
written `1.234,56`, dates `dd/mm/yyyy`, a few free lines before the table, then this header and one line per
transaction:

```
Extrato Conta Corrente
Período ;01/08/2026 a 31/08/2026
Saldo ;4.512,33

Data Lançamento;Histórico;Descrição;Valor;Saldo
31/08/2026;Pix enviado;PADARIA PAO DOURADO;-12,50;4.512,33
```

`Valor` is negative for money going out. `Saldo` (the balance after each line) is optional but lets the program check
the file. Both usual text encodings (UTF-8 and Latin-1) are read.

## Using another bank

If your bank exports something different, change only `finance_automation/statement.py`:

- a different header: change `HEADER` (the pattern that finds the first line of the table);
- different column order or names: change the column numbers read in `parse_text` (date, history, description,
  amount, balance);
- a comma separator or `1,234.56` numbers: change the `split(";")` call and `parse_brl` in `text.py`;
- no balance column: leave it empty; the balance check is then skipped.

Everything after that step (database, rules, AI, reports) stays the same. Add one small example file to `tests/` and
run the tests (`python -m pytest -q`).

## Privacy in detail

- **What goes to the API**, only for shops the rules do not know: the description, the bank's transaction type (for
  example "PIX ENVIADO") and whether money came in or out.
- **Names of private individuals never go.** In transfers, a description that looks like a person's name is replaced
  by `<PERSON>` before the request (`finance_automation/privacy.py`). Under Brazil's data protection law (LGPD) a name
  is personal data, so it is removed rather than shared. The check errs on the safe side: a one-person business shown
  only by a plain name is masked too. `tests/test_privacy.py` checks that no name reaches the request or the saved
  answers.
- **Never sent:** amounts, dates, balances, account numbers, the statement file or the database.
- **Stays on your computer:** the database (`data/ledger.sqlite`) and the call logs (`output/logs/`), both left out of
  git.

## Commands

| Command | What it does |
|---|---|
| `python demo.py` | the full example above (`--live` to call the API for questions never asked) |
| `python -m finance_automation import <file.csv>` | load a statement |
| `python -m finance_automation review` | list what waits for a person |
| `python -m finance_automation review --approve ID [--category X]` | confirm or correct one item |
| `python -m finance_automation report --month 2026-08` | write the monthly report |
| `python -m finance_automation eval` | check the AI against the answer key |

## Other limits

- Rules match words inside the description, so a very short keyword could catch the wrong shop; the review refuses
  keywords under 3 letters.
- A transfer to a person has no category the AI can know; those always go to review.
- The 31 test answers show the method works; they are not a benchmark.
